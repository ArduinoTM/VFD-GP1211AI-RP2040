## 这 3 帧能核对的量（本文件即可复现）

* 扫描周期 **189.05 µs**、帧率 **123.02 Hz**、BK 消隐 **119.03 µs** / 点亮 **70.02 µs**（默认亮度 200）；
* 每帧 48 个 CLKg 脉冲 = **5 播种**（CPU 帧末 `seedGrid()`，SIg=1,1,0,0,0，实测 3/3 组序列正确）+ **43 前进**；
* **BK 上升沿 → CLKg 前进沿 = 0.58…0.70 µs（均值 0.64）** —— `hardware/wiring.md` §4.1 的旧值 86.9 µs 属于
  「边界在数据段之后」的早期结构，已按本次实测订正；
* `tDS(SIa↔CLKa)` = **100 ns**、`tDH(SIa↔CLKa)` = **100 ns**（各 49 535 个样本），`tLS` = 101.92 µs（CLKa 版）/
  102.02 µs（SIa 版）—— 都远高于手册门限；
* Note 7②：129 个扫描的最后一次 CLKa 上升沿都早于 BK 下降沿，最小裕量 30.40 µs（点亮窗口内 0 次 CLKa 活动）。

## 门禁结果：**15/16 项 ✅**，唯一不合格是 `Note 7③`

| 项 | 现象 | 原因 / 归属 |
|---|---|---|
| `Note 7③` | 本样本（v1.3.1 固件）BK 跳变时 CLKg 为低 **6 次**（3 帧 × 2） | ✅ **2026-10-17 已修（`bc3acfc`）**：真因不是"结构性"，而是 `seedGrid()` 步进表**最后一步写成了 `0x0`（CLKg 低）**、注释误写"收尾回空闲" —— 而 CLKg 的空闲电平是**高**（手册 Figure 3/5、边界 ④ = `0x2`）⇒ 播种后 CLKg 一直低到下一次边界 ①，正好跨过帧首那条 **BK 上升沿**。四档验收抓包实测：4231 次 BK 跳变里 49 次（= 每帧 1 次）违规，且 49 次全部落在"播种 SIg 下降沿之后 17.5 µs"、其余 0 次。删掉末步（播种 12 → 11 步 ≈11.2 µs）即归零 —— **全绿样本已入库：`golden-pio-bc3acfc.csv.gz`（本目录）**，实测 4232 次 BK 跳变里 CLKg 为低 **0 次** |

## 再抓一次时的注意事项

1. 9 路探点：GP2 CLKa / GP3 SIa / GP4 LAT / GP5 CLKg / GP6 SIg / GP7 BK / GP8 HVEN / GP9 FLEN **+ 共地**；
2. 采样率 ≥ 50 MHz、**边沿压缩**导出；表头必须逐字是
   `Time[s], CLKa, SIa, LAT, CLKg, SIg, BK, HVEN, FLEN`（列名大小写不敏感）；
3. 长度 ≥ 3 帧（≈25 ms）即可判读全部项目；要更长可降到 5–10 MHz 或分段抓（见 `docs/00` §14.16）；
4. 记录被抓固件的 commit 与构建时间（启动横幅的 `fw:` 指纹行）—— 历史上出现过「文件 SHA 一样但抓包对不上」；

**首轮（修复前固件）曾报 2 项 ❌，根因与修法**：

| 项 | 现象 | 根因 / 修法 |
|---|---|---|
| `Note 7③` | 每次扫描 BK↑ 时 CLKg 已为低（2115/2116） | `pwm_set_counter()` 写的是 PWM **计数寄存器**，输出比较跟着 PWM 自己的 1 µs 计数时钟走 ⇒ 写寄存器到引脚翻转滞后 ≈0.3–1 µs；而 SIO 写 CLKg 几乎立刻到引脚 ⇒ 引脚上成了"CLKg 先低、BK 后高"。修法：写 CTR 后**等 BK 在引脚上真的变高**再走边界四步（`1e50309`） |
| 帧首 SIg 序列 | 49 个 6 连发组的 SIg = 0,1,1,0,0,0 | 帧末播种原来"紧跟 A42 之后"，播种组于是与 A42 的前进脉冲并成一组；pio（实机验证过）的形态是"播种 5 个紧跟**帧首那 1 个前进**"（1,1,0,0,0,0）。修法：帧末播种改为"点亮起点 +1 µs"再播（`89ad18a`） |

**tick 与 pio 的两处已知差异**（都不是违规，判读时按这两条读表）：

* **播种落点**：两个引擎**同形** —— 播种在整帧最后一次扫描、等点亮起点之后播。判读工具会看到
  5 连发 `11000`（隔离，本样本 49/49）或 6 连发 `110000`（播种 5 个紧跟帧首那 1 个前进，lit 较小时出现）；
  `check_seed_window.js` 的"起点电平"两引擎都报 **BK低(点亮)**（播种落在点亮窗口内；LAT 全程低 ⇒ 屏幕上不可见），
  到下一 LAT 的余量随亮度在 ≈17–150 µs 之间。
* **落点边界**：pio 的共享边界是 98/102 µs；tick 的搬运 86 µs + 边界四步 ≈6.5 µs（含"等 BK 在引脚上变高"
  与让位）装不下更长的消隐窗口 ⇒ tick 的**低亮度落点上限是 95 µs**（`TICK_LIT_LOW_MAX_US`），
  `lit ≥ 96 µs`（b ≥ 136）改走**点亮**落点（余量 ≥9 µs）。**四档验收（38/92/110/151）不含这几档**；
  扫亮度时若在 b ≈136 处看到落点切换属预期。
