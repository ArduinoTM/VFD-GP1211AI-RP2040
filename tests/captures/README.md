# tests/captures —— 逻辑分析仪黄金样本

| 文件 | 内容 | 来源 |
|---|---|---|
| `golden-pio-v1.3.1.csv.gz` | PIO 引擎、**3 帧**（24.387 ms / 100 070 行）裁剪样本，时间轴归零；50 MHz 边沿压缩导出（时间基准 20 ns） | 2026-10-16 上机抓包 `Timing-PIO-v1.3.1.csv`（原文件 952.392 ms / 117.19 帧 / 3 906 599 行） |

**为什么入库**：第三方评审 P7 指出「LA 合规门禁在仓库里无法被任何人复跑」（`*.csv` 被 `.gitignore` 排除）。
本样本让**没有硬件**的人也能复跑判读工具与门禁：

```powershell
node tests/tools/analyze_la_csv.js tests/captures/golden-pio-v1.3.1.csv.gz --compliance
```

原文件约 140 MB 不宜入库，故裁到 3 帧（够 3 个播种段 + 129 次扫描）再 gzip ⇒ **254 KB**；
判读脚本支持 `.csv.gz`（`openCsv()`，Node `zlib`，无第三方依赖）。

## 这 3 帧能核对的量（本文件即可复现）

* 扫描周期 **189.05 µs**、帧率 **123.02 Hz**、BK 消隐 **119.03 µs** / 点亮 **70.02 µs**（默认亮度 200）；
* 每帧 48 个 CLKg 脉冲 = **5 播种**（CPU 帧末 `seedGrid()`，SIg=1,1,0,0,0，实测 3/3 组序列正确）+ **43 前进**；
* **BK 上升沿 → CLKg 前进沿 = 0.58…0.70 µs（均值 0.64）** —— `hardware/wiring.md` §4.1 的旧值 86.9 µs 属于
  「边界在数据段之后」的早期结构，已按本次实测订正；
* `tDS(SIa↔CLKa)` = **100 ns**、`tDH(SIa↔CLKa)` = **100 ns**（各 49 535 个样本），`tLS` = 101.92 µs（CLKa 版）/
  102.02 µs（SIa 版）—— 都远高于手册门限；
* Note 7②：129 个扫描的最后一次 CLKa 上升沿都早于 BK 下降沿，最小裕量 30.40 µs（点亮窗口内 0 次 CLKa 活动）。

## 门禁结果：**15/16 项 ✅**，唯一不合格是 `Note 7③`

| 项 | 现象 | 原因 / 归属 |
|---|---|---|
| `Note 7③` | BK 跳变时 CLKg 为低 **6 次**（3 帧 × 2） | **结构性**：`seedGrid()` 播完第 5 个播种脉冲后 CLKg 停在**低**电平，直到下一帧首扫描的边界 ② 才抬回高（≈65 µs，正好跨过 BK 下降沿与上升沿）。2026-10-11 之前"播种在 PIO 程序内"的版本没有该现象（`docs/00` §8.10 的旧抓包为 **0 次**）。消除它要把播种搬回 PIO / 自循环 DMA（`docs/08` §7 的 **P6**，已定"留给后续"） |

其余 **15 项 judge 全部 ✅**：fCLK 4.440 MHz、tWCLK、tDS/tDH(SIg)、**tDS/tDH(SIa)**、tWL(CLKg)、tWL(LAT)、
tLS、tLH、刷新率、Note 16、Note 7①②④、Note 14。
（`tLS` 按手册定义「最后一个 CLKa 上升沿 → LAT 有效沿」判定，SIa 版作为**附加**判据。）

## 再抓一次时的注意事项

1. 9 路探点：GP2 CLKa / GP3 SIa / GP4 LAT / GP5 CLKg / GP6 SIg / GP7 BK / GP8 HVEN / GP9 FLEN **+ 共地**；
2. 采样率 ≥ 50 MHz、**边沿压缩**导出；表头必须逐字是
   `Time[s], CLKa, SIa, LAT, CLKg, SIg, BK, HVEN, FLEN`（列名大小写不敏感）；
3. 长度 ≥ 3 帧（≈25 ms）即可判读全部项目；要更长可降到 5–10 MHz 或分段抓（见 `docs/00` §14.16）；
4. 记录被抓固件的 commit 与构建时间（启动横幅的 `fw:` 指纹行）—— 历史上出现过「文件 SHA 一样但抓包对不上」；
5. 若 `Note 7③` 按 P6 修掉，本样本的"已知不合格"一项应随之消失：届时替换样本并更新本文件。
