# GP1211AI VFD 驱动（RP2040 / Pico）综合技术报告

> 精简版：由开发期的完整文档集（原驱动不足分析、移植说明、PIO 引擎、实测技术报告、SSD1306 行为模拟、
> 排故报告等）压缩而成，只保留**结论、依据与取舍**，篇幅约 1/6，便于快速通读与接手。

## 1. 项目概述

把 **GP1211AI / Noritake MN12864K 128×64 VFD**（无显示控制器，纯玻璃屏 + 驱动板）的
STM32F103 Arduino 驱动移植到 **RP2040 / Raspberry Pi Pico（Pico SDK, C++17 + CMake）**，
并修掉原驱动的一批规格合规与健壮性问题。算法与位映射源自
[VFD-GP1211AI](https://github.com/Trigger-CN/VFD-GP1211AI)（MIT）。

* 提供两种扫描引擎，编译期二选一，**输出到屏上的时序效果一致**：
  * **tick**：`repeating_timer`（189 µs/扫描）+ SPI0（4.46 MHz, MODE3）+ DMA，CPU ≈2%；
  * **pio**：PIO 状态机产生 CLKa/SIa/CLKg/LAT/SIg + 整帧 DMA，CPU ≈0.06%（原驱动 ≈24% 忙等）。
* 附带 **SSD1306 行为模拟**：可把这块 VFD 当"一片 128×64 的 SSD1306 OLED"用，主机侧用现成
  库（Adafruit_SSD1306 / u8g2…）经 4 线 SPI 送画面即可，无需改主机代码。
* 帧缓冲 1 KB + 双缓冲发送缓冲 2×2064 B；产物 uf2 136 KB（诊断开）/ 114 KB（诊断关）。

## 2. 硬件与手册要点

屏由 **48 位栅极链 + 384 位阳极链**驱动，一帧 43 个时序（T1…T43），每个时序选通相邻两个栅极
（(G1,G2)…(G43,G44)）：

| 手册条款 | 内容 | 本移植的处理 |
|---|---|---|
| Note 7① | CLK 空闲高 | SPI MODE3 / PIO sideset 满足 |
| Note 7②③④ | 数据传输期间 BK 不得变化 | "一 PWM 周期 = 一扫描周期"，数据只在消隐窗口搬 |
| Note 10/11/12 | T 奇 → a,b,c；T 偶 → d,e,f；**T43 只用 a,b**（c,d,e,f 全 OFF） | 位重排阶段实现（见 §4） |
| Note 14 | 栅极扫描停止可能**永久损坏**屏 | 扫描心跳看护：停摆自动恢复，连续失败先关高压再停扫 |
| Note 15 | LATg 应常高（透明） | 本板 LATa/LATg 并联，无法分离 ⇒ 用"先前进、再锁存"的边界顺序等效 |
| Note 16 | 桁间消隐 ≥ 5 µs | 实测 ≈100 µs |
| 电气 | fCLK ≤ 5 MHz；45 V VDD2、2.9 Vac 灯丝 | 4.46 MHz（tick）/ 4.5 MHz（pio）；高压调试时先断开 |

**引脚（默认，可用 `-DVFD_PIN_*` 覆盖）**：GP2 CLKA、GP3 SIA、GP4 LAT、GP5 CLKG、GP6 SIG、
GP7 BK、GP8 HVEN、GP9 FLEN；GP11–GP15 = 主机侧 SCK/MOSI/DC/CS/RESET（SSD1306 从机，
DC 必须紧邻 MOSI）；GP16 = 测试模式（上电为低才渲染内置测试图像）。

## 3. 软件架构

```
vfd_scanpack.{h,cpp}   平台无关：帧缓冲 → 每时序 384 bit（48 字节）位重排（纯函数，可宿主测试）
vfd_gp1211ai.{h,cpp}   驱动层（继承 Adafruit_GFX）：绘图原语 + 双缓冲发布 + 扫描看护
vfd_platform.h         硬件抽象：换 MCU 只需实现它
vfd_platform_rp2040.*  两引擎共用：引脚/上电/亮度 PWM/发布/看护
  ├─ ..._tick.cpp      tick 引擎：repeating_timer + SPI + DMA
  └─ ..._pio.cpp       pio  引擎：PIO 状态机 + 整帧 DMA
ssd1306_emulator.*     SSD1306 行为模拟核心（命令/GDDRAM/寻址/渲染）
ssd1306_slave_rp2040.* 4 线 SPI 从机传输层（PIO + DMA 环形缓冲）
```

位映射沿用原驱动与手册数据号：`k = 48*page + 6*m + off`（k = 384 bit 链里的位号，k=0 最先移出），
`off` 为 6 个阳极槽之一。槽位与字母的对应由手册 Sheet 6 的 `a,f,b,e,c,d` 顺序与移位方向
（SIa → 384…1 → SOa）推出：**off 5=a、3=b、1=c、0=d、2=e、4=f**。

## 4. 扫描时序：实机定标结论（已固化进实现，不是编译开关）

| 项 | 结论 | 依据/位置 |
|---|---|---|
| LAT 极性 | **空闲低、锁存打正脉冲** | 驱动电路无反向器，手册 Figure 3 画的就是正脉冲；`.pio` 的 set 组 / tick 的 `vfdLatPulse()` |
| CLKg 极性 | **空闲高**；低→高脉冲的上升沿 = 栅极链前进一位 | 同上 |
| 扫描边界 | **四步**：① CLKg 拉低 → ② CLKg↑ **前进** → ③ LAT↑ **锁存** → ④ LAT↓ 释放（**先前进、再锁存**） | 顺序反了会让画面整体平移 3 列（抓包实测旧波形里 LAT 比 CLKg 早 ≈440 ns） |
| 帧首播种 | 由 **CPU** 在帧末 DMA 完成中断里执行（SIg = 1,1,0,0,0 五个 CLKg 脉冲），**全程保持 LAT 低**（否则链搬运可见 ⇒ 边缘闪烁/线框抖动），并等 BK 点亮窗口再发以保证落点确定 | `seedGrid()` / `onFrameDmaDone()` |
| 带内 3 列槽序 | **原驱动约定**：`t 偶 → off 0,2,4`、`t 奇 → off 5,3,1`（t = 42 − 扫描号） | `packScan()`；实机用"运行时轮换"诊断固件选出 |
| 扫描相位 | **−1**：边界锁存的是**上一扫描**移入的 48 字节 ⇒ 数据侧提前一个扫描发 | `wirePrepareFrame()` |
| T43 | 手册 Note 12：只用 a,b ⇒ `off 2 / off 4`、`k` 整体 −2、只写两个槽 | `packScan()` 的 `t43` 分支（同样由实机变体扫描定标） |
| 数据段 | 逐 bit 消费（`set y,2` + `set x,15` + `jmp x--` + `jmp y--`，程序 25/32） | 曾用"每扫描一个控制字 + `out x,32` 按字读 OSR"，因 OSR 初始 32 bit 会让整条流错位而废弃 |
| 两条 `wait` | 不可省（一次扫描只有 ≈88 µs，结束时 BK 仍为消隐高电平） | `src/vfd_scan.pio`；省一条会 ~2 倍速跑飞并停在 `out` |

> 定标方法（可复用）：把候选参数做成**运行时表 + 每 2.5 s 轮换**的诊断固件，实机看着屏报编号，
> 一两轮即可收敛；比"改一次代码烧一次"快一个数量级。

## 5. SSD1306 行为模拟

主机侧代码与驱动真实 OLED 完全相同（**SPI 模式 0**，SCK/MOSI/DC/CS/共地）。支持：

* 显示开关、全亮（`0xA5`）、反显（`0xA7`）、`0x81` 对比度 → VFD 亮度、RESET；
* 页寻址 / 水平寻址 / 垂直寻址，列页窗口与回绕；
* **滚动**：`0x26/0x27`（水平右/左）、`0x29/0x2A`（垂直+水平）、`0x2E/0x2F`（停止/启动），
  间隔按规格书帧数表折算（1 帧 = 8 ms）；`0xA3` 垂直滚动区、`0xA8` 多路复用比只记录；
* 未知命令忽略并计数；参数跨多次写入可拆开。

段/COM 重映射按"标准模块"约定：库默认的 `0xA1`+`0xC8` 与主机缓冲同向（逐位一致）。

**限制**：只支持 SPI 模式 0；渲染有 12 ms 节流（最高 83 fps，足够最快档滚动）；
滚动时间基准是折算值；从机环形缓冲 1 KB，异常突发会计数 `overrunCount()` 并自动重新对齐；
整帧重排 + 双缓冲模型约占 4 KB RAM。

## 6. 与原驱动的差异（要点）

| 项 | 原驱动（STM32F103） | 本移植（RP2040） |
|---|---|---|
| 阳极时钟 | `setClock(12e6)` 实跑 ≈9 MHz（超手册 5 MHz） | 4.46 MHz / MODE3 |
| 数据搬运 | ISR 阻塞式 `SPI.write`，≈24% CPU | DMA，ISR 只翻引脚，≈1–2% |
| 调光 | BK 94 kHz 自由 PWM（违反 Note 7②） | 一 PWM 周期 = 一扫描周期，只在本扫描消隐窗口搬数据 |
| 桁间消隐 | 无显式实现 | ≈100 µs |
| 帧缓冲/撕裂 | `display()` 与 ISR 共用一块缓冲 | 双缓冲 + 帧边界握手，任意调用节奏不撕裂 |
| 扫描保护 | 无 | 心跳看护 → 自动恢复 → 连续失败关高压 |
| 其它 | 颜色 ≥3 静默丢弃、`invertDisplay()` 无效、`fillScreen(INVERSE)` 变白、`setRotation()` 越界写坏缓冲、列 128 越界读 UB | 分别改为归一化 WHITE、生效、整体取反、拒绝非 0 旋转、显式跳过 |

## 7. 验证

* **宿主机测试**（`tests/run_host_tests.ps1`，只需 g++，不需要嵌入式工具链）：
  5 个程序共 **241 项** —— 位重排与原驱动 1:1 转录逐位对比、双射校验、双缓冲无撕裂回归、
  看护逻辑、示例画面 ASCII 预览、SSD1306 模拟核心（含滚动）、从机 PIO 线上格式、主控相位序列回放；
* **SDK 形状桩语法检查**：13 个目标机源码组合 + 3 个 `.ino` 语法检查；
* **实机**：tick 与 pio 两引擎在真实屏上均确认正常（内容、位置、极性、T43 全对）；
* **逻辑分析仪判读**：`tests/tools/` 下有抓包渲染、合规核对、位序反解等 node 脚本，
  用于把"屏上看到的"与"总线上发的"逐位对齐。

## 8. 已知取舍

* **峰值亮度 ≈47%**：为满足 Note 7②，阳极数据只在消隐窗口搬，点亮窗口最大 ≈89/189。
  tick 受限于 48 字节移位时间（≈86 µs），pio 受限于 795 周期的数据阶段（≈88 µs）；
  `init()` 会自检，必要时抬高 `blank_guard_us`，余量可用 `guardMarginUs()` 读出。
* pio 引擎的**数据通路仍依赖 CPU 换帧**：CPU 长时间不响应帧中断时 DMA 停供、状态机卡在 `out`
  （`engineStalled()` 可查）。要做到完全脱离 CPU，可把整帧 DMA 做成自循环控制块链。
* pio 引擎靠 BK 引脚的电平沿同步，因此亮度 0 时仍保留 1 µs 点亮窗口（占空 0.5%，视觉等同全黑）。
