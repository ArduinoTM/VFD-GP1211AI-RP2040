## 1. 项目概述

把 **GP1211AI / Noritake MN12864K 128×64 VFD**（无显示控制器，纯玻璃屏 + 驱动板）的
STM32F103 Arduino 驱动移植到 **RP2040 / Raspberry Pi Pico（Pico SDK, C++17 + CMake）**，
并修掉原驱动的一批规格合规与健壮性问题。算法与位映射源自
[VFD-GP1211AI](https://github.com/Trigger-CN/VFD-GP1211AI)（MIT）。

* 提供两种扫描引擎，编译期二选一，**输出到屏上的时序效果一致**：
  * **tick**：`repeating_timer`（189 µs/扫描）+ SPI0（目标 4.5 MHz，实测 4.464 MHz = 125 MHz/28，MODE3）+ DMA，CPU ≈2%；
  * **pio**：PIO 状态机产生 CLKa/SIa/CLKg/LAT/SIg + 整帧 DMA，CPU ≈0.06%（原驱动 ≈24% 忙等）。
* 附带 **SSD1306 行为模拟**：可把这块 VFD 当"一片 128×64 的 SSD1306 OLED"用，主机侧用现成
  库（Adafruit_SSD1306 / u8g2…）经 4 线 SPI 送画面即可，无需改主机代码。
* 帧缓冲 1 KB + 双缓冲发送缓冲 2×2064 B。产物 uf2（Release；**诊断关 / 诊断开**）：
  tick 单核 **135 / 152 KB**、pio 单核 **135 / 152 KB**、双核 **145.5 / 145 KB**（tick / pio；诊断关 / 诊断开；2026-10-17 全部 `-Clean` 重建）。
* **可选双核分工**（`-DVFD_DUAL_CORE=ON`，默认关）：把 SSD1306 数据面整个搬到 core1，
  core0 只留扫描时序 + 帧发布 + 看护；关闭时与单核逐行为一致。

## 2. 硬件与手册要点

屏由 **48 位栅极链 + 384 位阳极链**驱动，一帧 43 个时序（T1…T43），每个时序选通相邻两个栅极
（(G1,G2)…(G43,G44)）：

| 手册条款 | 内容 | 本移植的处理 |
|---|---|---|
| Note 7① | CLK 空闲高 | SPI MODE3 / PIO sideset 满足 |
| Note 7②③④ | 数据传输期间 BK 不得变化 | "一 PWM 周期 = 一扫描周期"，数据只在消隐窗口搬 |
| Note 10/11/12 | T 奇 → a,b,c；T 偶 → d,e,f；**T43 只用 a,b**（c,d,e,f 全 OFF） | 位重排阶段实现（见 §4） |
| Note 14 | 栅极扫描停止可能**永久损坏**屏 | 扫描心跳看护：停摆自动恢复；连续失败 **fatal 停泊**（先关高压、再关断灯丝驱动、BK 全消隐、停扫描；板载 LED 常亮） |
| Note 15 | LATg 应常高（透明） | 本板 LATa/LATg 并联，无法分离 ⇒ 用"先前进、再锁存"的边界顺序等效 |
| Note 16 | 桁间消隐 ≥ 5 µs | 实测 ≈100 µs |
| 电气 | fCLK ≤ 5 MHz；45 V VDD2、2.9 Vac 灯丝 | 4.5 MHz（tick 实测 4.464 MHz、pio 4.5 MHz）；高压调试时先断开 |

**引脚（默认，可用 `-DVFD_PIN_*` 覆盖）**：GP2 CLKA、GP3 SIA、GP4 LAT、GP5 CLKG、GP6 SIG、
GP7 BK、GP8 HVEN、GP9 FLEN；GP11–GP15 = 主机侧 SCK/MOSI/DC/CS/RESET（SSD1306 从机，
DC 必须紧邻 MOSI）；GP16 = 测试模式（上电为低才渲染内置测试图像）；
**GP25 = 板载状态 LED**（正常 1 Hz 心跳闪烁、fatal 停泊后常亮；`-DVFD_PIN_LED=255` 关闭，Pico W 自动不驱动）。

## 3. 软件架构

```
vfd_scanpack.{h,cpp}   平台无关：帧缓冲 → 每时序 384 bit（48 字节）位重排（纯函数，可宿主测试）
vfd_gp1211ai.{h,cpp}   驱动层（继承 Adafruit_GFX）：绘图原语 + 双缓冲发布 + 扫描看护
vfd_platform.h         硬件抽象：换 MCU 只需实现它
vfd_platform_rp2040.*  两引擎共用：引脚/上电/亮度 PWM/发布/看护
  ├─ ..._tick.cpp      tick 引擎：repeating_timer + SPI + DMA
  └─ ..._pio.cpp       pio  引擎：PIO 状态机 + 整帧 DMA
ssd1306_emulator.*     SSD1306 行为模拟核心（命令/GDDRAM/寻址/渲染）
ssd1306_slave_rp2040.* 4 线 SPI 从机传输层（PIO + DMA 环形缓冲）
dualcore_handoff.h     双核核间 2 槽 SPSC 协议（纯逻辑：槽位 / 丢帧守卫 / 最新帧选择）
```

位映射沿用原驱动与手册数据号：`k = 48*page + 6*m + off`（k = 384 bit 链里的位号，k=0 最先移出），
`off` 为 6 个阳极槽之一。槽位与字母的对应由手册 Sheet 6 的 `a,f,b,e,c,d` 顺序与移位方向
（SIa → 384…1 → SOa）推出：**off 5=a、3=b、1=c、0=d、2=e、4=f**。

### 3.1 双核分工（可选：`-DVFD_DUAL_CORE=ON`，默认关）

| | core0 | core1 |
|---|---|---|
| 扫描引擎（tick 的 `scanTick` / pio 的 `onFrameDmaDone`、播种、recover、`emergencyOff`） | ✅ | — |
| 帧发布 `display()`（打包 + 相位 −1 + 帧边界握手） | ✅ | — |
| 看护 `display.task()`、stdio | ✅ | — |
| SSD1306 数据面（排水 / 解码 / 滚动 / 渲染） | — | ✅ |

资源天然不冲突：扫描引擎用 pio0/SPI0 + DMA0/1，SSD1306 从机用 pio1 + DMA2。
核间用 **2 槽 SPSC 双缓冲 + 单调序号**：core1 写槽 `seq % 2` → `__dmb()` → `seq++`；
core0 见 `seq` 变化 → 读槽 → 发布 → `ack`。帧 k 与 k−2 共用一槽 ⇒ 只有 `seq - ack <= 2` 才允许生产，
否则丢本帧（**宁丢帧、不撕裂**）。对比度走两个 `volatile` 小消息，不用阻塞式 FIFO。

诊断里给出 **4 个忙时子项**可直接量收益：单核 `core0: irq / drain / render / work`，
双核 `core0: irq / work | core1: drain / render`（一一对应，`1% = 10000 µs`）。

> ⚠️ 双核下必须核对内存布局：`main()` 的栈只有 2048 B，任何 >1 KB 的局部对象都可能溢出到
> core1 的栈（SCRATCH_X）。常驻对象一律放文件级 `static`（.bss）。

## 4. 扫描时序：实机定标结论（已固化进实现，不是编译开关）

| 项 | 结论 | 依据/位置 |
|---|---|---|
| LAT 极性 | **空闲低、锁存打正脉冲** | 驱动电路无反向器，手册 Figure 3 画的就是正脉冲；`.pio` 的 set 组 / tick 的 `vfdLatPulse()` |
| CLKg 极性 | **空闲高**；低→高脉冲的上升沿 = 栅极链前进一位 | 同上 |
| 扫描边界 | **四步**：① CLKg 拉低 → ② CLKg↑ **前进** → ③ LAT↑ **锁存** → ④ LAT↓ 释放（**先前进、再锁存**） | 顺序反了会让画面整体平移 3 列（抓包实测旧波形里 LAT 比 CLKg 早 ≈440 ns） |
| 帧末播种 | 由 **CPU** 在**整帧最后一次扫描**执行（SIg = 1,1,0,0,0 五个 CLKg 脉冲），**全程保持 LAT 低**（否则链搬运可见 ⇒ 边缘闪烁/线框抖动），并**等点亮起点之后**再发（pio 在帧末 DMA 完成中断里、tick 在一次性闹钟里）；位置在 A42 之后、A0 之前，与「帧首扫描边界之前」逐位等价。**末步必须把 CLKg 留在高**（pio 曾把末步写成 CLKg 低 ⇒ 每帧 1 次 Note 7③） | `seedGrid()` / `onFrameDmaDone()` / tick 的 `triggerThunk()` |
| 带内 3 列槽序 | **原驱动约定**：`t 偶 → off 0,2,4`、`t 奇 → off 5,3,1`（t = 42 − 扫描号） | `packScan()`；实机用"运行时轮换"诊断固件选出 |
| 扫描相位 | **−1**：边界锁存的是**上一扫描**移入的 48 字节 ⇒ 数据侧提前一个扫描发 | `wirePrepareFrame()` |
| T43 | 手册 Note 12：只用 a,b ⇒ `off 2 / off 4`、`k` 整体 −2、只写两个槽 | `packScan()` 的 `t43` 分支（同样由实机变体扫描定标） |
| 数据段 | 逐 bit 消费（`set y,2` + `set x,15` + `jmp x--` + `jmp y--`，程序 25/32） | 曾用"每扫描一个控制字 + `out x,32` 按字读 OSR"，因 OSR 初始 32 bit 会让整条流错位而废弃 |
| **搬运落点**（2026-10-17「选项 C」） | 按亮度二选一：**高亮度（点亮 ≥ 102 µs）搬运整段落在点亮窗口内**（手册 Figure 5 形态）；**低亮度整段落在消隐窗口内**（BK 在搬运期间不变 ⇒ Note 7② 仍成立）。亮度区间 **20%–80%（38–151 µs）**，两段线性 + 跳过 4 µs 死区。tick 与 pio 共用同一份映射与边界（tick 低亮度上限 95 µs、pio 98 µs，因两者搬运/边界耗时不同） | `src/vfd_pio_seed_timing.h`（唯一来源 + 编译期 `static_assert` 互锁）、`src/vfd_platform_rp2040_pio.cpp`（指令补丁）/ `..._tick.cpp`（边界 + 一次性闹钟）；判据 `tests/tools/check_seed_window.js`、`analyze_la_csv.js --compliance` |
| 两条 `wait` | 不可省（一次扫描只有 ≈89 µs，结束时 BK 仍为消隐高电平） | `src/vfd_scan.pio`；省一条会 ~2 倍速跑飞并停在 `out` |

> 定标方法（可复用）：把候选参数做成**运行时表 + 每 2.5 s 轮换**的诊断固件，实机看着屏报编号，
> 一两轮即可收敛；比"改一次代码烧一次"快一个数量级。

## 5. SSD1306 行为模拟

主机侧代码与驱动真实 OLED 完全相同（**SPI 模式 0**，SCK/MOSI/DC/CS/共地）。支持：

* 显示开关、全亮（`0xA5`）、反显（`0xA7`）、`0x81` 对比度 → VFD 亮度、RESET；
* 页寻址 / 水平寻址 / 垂直寻址，列页窗口与回绕；
* **滚动**：`0x26/0x27`（水平右/左，**6 个参数**）、`0x29/0x2A`（垂直+水平，**5 个参数** —— 结尾没有第二个
  空字节，主机库紧跟的 `0x2F` 必须被当成"启动"命令）、`0x2E/0x2F`（停止/启动），间隔按规格书帧数表折算
  （1 帧 = 8 ms）。两条通路与真机一致：**水平改写 GDDRAM**（`0x2E` 停止后位移保留），
  **垂直是显示级上移**（只能向上；`0x2E` 停止后上下自动复位、左右保留）。`0xA3` 垂直滚动区已实现
  （顶固定行数 / 滚动区行数，复位默认 `00 40` = 全区；`A+B>64` 截断、`B=0` 收敛为全区）；
  `0xA8` 多路复用比只记录；
* 未知命令忽略并计数；参数跨多次写入可拆开；
* **失步看护**：硬件报 RXSTALL（时钟/数据受干扰导致 PIO 停摆）时立刻停 SM 与 DMA、丢弃本帧剩余字节
  并重新对齐（最多损失一帧，不会整屏错位），CS 抬起等待有 20 ms 上限兜底；
  诊断计数 `stallfix`（看护触发）/ `stallforced`（其中强制对齐）正常恒 0。

段/COM 重映射按"标准模块"约定：库默认的 `0xA1`+`0xC8` 与主机缓冲同向（逐位一致）。

**上电即抓取**：主机接收通路（PIO + DMA，与扫描引擎资源零交集）在 `main()` 一开始就启动，
**早于** 20+400+20 ms 的灯丝预热与启动横幅；上电时序本身也改成非阻塞
（`VFD_GP1211AI::beginAsync()` + `pumpPowerUp()`，基类 `Platform::powerUpBegin()/powerUpPoll()`）——
预热期间单核由主循环切片排水、双核由 core1 数据面全程排水 ⇒ 复位后主机立刻发来的初始化序列与
首批画面不会丢（旧顺序下复位后前 ~500 ms 的字节根本没被采样，且计数从 0 起算，丢了看不见）。
横幅里的 `boot capture: N B received before this loop (overrun=… drop=…)` 就是这段窗口的核对点。

主机侧仍建议**上电 ≥150 ms 后再发初始化**（或先把 RESET 拉低 ≥150 ms 再释放，本机在 RESET 上升沿
会复位模拟器状态）：RP2040 自身启动的几十毫秒无法接收任何字节。另外，只复位 RP2040 而主机继续跑时，
主机不会重发初始化 ⇒ 本机从默认态（显示关）起来会保持全黑 —— 真 SSD1306 被单独复位后同样如此。

**主机侧接入要点**：主机用现成库即可（`examples/` 下有 u8g2 与 Adafruit 两个可烧的样例，
另有 `wiring_probe_due_r4` 分相接线探针）。三条最容易踩的坑：

1. ⚠️ **Adafruit_SSD1306 默认 8 MHz，必须显式 `setBusClock(4000000)`** —— 4 MHz 是本文档验证过的档位
   （8 MHz 的余量见 §8）；
2. **DC/CS 不要选在主机 SPI 外设自己的脚上**：Arduino Due 的硬件 SPI **只在 2×3 ICSP 排针**
   （ICSP-3=SCK/GPIO76、ICSP-4=MOSI/GPIO75；数字口 11/12/13 不是 SPI）；Uno R4 Minima 是 **5 V**，
   直连超规格（需电平转换或先降到 1 MHz 短时试）；
3. 上电后 **≥150 ms** 再发初始化（本机自身启动的几十毫秒收不到字节），且不要写 `while (!Serial);`。

**长阻塞期间的排水义务**（2026-10 修复）：`display()` 等帧边界（最长 40 ms）、逐秒诊断打印（100+ ms）
这类长阻塞里必须**持续取走**从机环形缓冲的数据 —— 4 MHz 下 16 KB 环 8.2 ms 就被主机灌满一圈。
实现：帧边界等待挂应用层钩子、诊断输出**一律 32 B 分块 + 块间排水**（硬约束：不允许"整行一次写出"，
这正是一次 19.8 ms 无排水窗口的根因）、主循环的排水与打印/钩子共用同一个入口。

**诊断与余量**：诊断每秒打印一次，其中两项直接决定"能不能加频"：

* 启动横幅的 `fw: <编译日期 时间> rx drain(tick): … wait-hook=on print-drain=serviceLink`
  —— 唯一标识板上跑的是哪一版固件（排故先看它）；
* `gapmax=<µs>(起点段→终点段,rx+NB,big=N)` —— 本窗口"最长有多久没把主机数据取走"，
  以及**当时主机是否在发**（`rx+0` ⇒ 没发，无害）。

危险线 = 从机可用缓冲 4094 B ÷ 主机字节率 ⇒ **1 MHz 32.8 ms ｜ 4 MHz 8.19 ms ｜ 8 MHz 4.09 ms ｜ 10 MHz 3.28 ms**。
实测（4.464 MHz、主机持续送帧、诊断开）：修复后 `gapmax` = **2.79 ms**，正好等于"一个 32 B 诊断分块的
串口时间" ⇒ 已触到 `-Diag on` 的地板（主循环里没有别的阻塞源），`overrun/drop` 全程 0。
量产 `-Diag off` 没有打印块，`gapmax` 只会更小。

**限制**：只支持 SPI 模式 0；渲染有 12 ms 节流（最高 83 fps，足够最快档滚动）；
滚动时间基准是折算值；从机环形缓冲 **16 KB**（4096 字节容量，可整装 4 屏），异常突发会计数
`overrunCount()`/`droppedCount()` 并**保留最新**数据、自动重新对齐；
整帧重排 + 双缓冲模型约占 4 KB RAM。

## 6. 与原驱动的差异（要点）

| 项 | 原驱动（STM32F103） | 本移植（RP2040） |
|---|---|---|
| 阳极时钟 | `setClock(12e6)` 实跑 ≈9 MHz（超手册 5 MHz） | 目标 4.5 MHz（tick 实测 4.464 MHz）/ MODE3 |
| 数据搬运 | ISR 阻塞式 `SPI.write`，≈24% CPU | DMA，ISR 只翻引脚，≈1–2% |
| 调光 | BK 94 kHz 自由 PWM（违反 Note 7②） | 一 PWM 周期 = 一扫描周期，只在本扫描消隐窗口搬数据 |
| 桁间消隐 | 无显式实现 | ≈100 µs |
| 帧缓冲/撕裂 | `display()` 与 ISR 共用一块缓冲 | 双缓冲 + 帧边界握手，任意调用节奏不撕裂 |
| 扫描保护 | 无 | 心跳看护 → 自动恢复 → 连续失败**停泊**（关高压 + 关灯丝驱动 + LED 常亮） |
| 其它 | 颜色 ≥3 静默丢弃、`invertDisplay()` 无效、`fillScreen(INVERSE)` 变白、`setRotation()` 越界写坏缓冲、列 128 越界读 UB | 分别改为归一化 WHITE、生效、整体取反、拒绝非 0 旋转、显式跳过 |

## 7. 验证

* **宿主机测试**（`tests/run_host_tests.ps1`，只需 g++，不需要嵌入式工具链）：
  6 个程序共 **343 项**（79+122+46+53+43）—— 位重排与原驱动 1:1 转录逐位对比、双射校验、双缓冲无撕裂回归、
  看护逻辑、示例画面 ASCII 预览、SSD1306 模拟核心（含滚动的两条通路、`0xA3` 垂直滚动区、
  `0x2E` 停止后垂直复位而水平保留、Adafruit 库真实滚动字节流回放）、从机 PIO 线上格式、
  主控相位序列回放、帧边界等待钩子；
* **核间握手回归**：`dualcore_handoff` **79102 项**（2 槽 SPSC 协议的全状态组合）；
* **SDK 形状桩语法检查**：**17** 个目标机源码组合（引擎 / 诊断 / 双核的交叉）+ **6** 个 `.ino`
  （含 Adafruit_SSD1306 / u8g2 / Due 探针的形状桩）；
* **双核实机**：core1 承载 SSD1306 数据面，画面与单核一致；core0 帧边界抖动无退化；
* **实机**：tick 与 pio 两引擎在真实屏上均确认正常（内容、位置、极性、T43 全对）；
  SSD1306 从机 4 MHz 长跑 `overrun/drop = 0`；失步看护 120 s + 141 s 两轮 0 触发；
  `gapmax` 从 19.8 ms 修到 **2.79 ms**（= 诊断地板），另有两组 A/B 实验证明 tick 的
  RX 排空 DMA 与 CPU 排空只是优化、不是正确性要求（`dma_busy_err` 恒 0）；
* **逻辑分析仪判读**：`tests/tools/` 下有抓包渲染、合规核对、位序反解、播种窗口等 node 脚本；
  其中 `analyze_la_csv.js --compliance` 可当**验收门禁**（不合格退出码非 0，**不可测量也算失败**），
  `check_seed_window.js` 核对帧末播种落点；`tests/captures/` 备有 pio 与 tick 两份**全绿黄金样本**
  （3 帧裁剪 + gzip），**没有硬件也能复跑这两条门禁**；
* **四档亮度抓包验收（2026-10-17，两个引擎）**：对比度 `0x00/0x80/0xA0/0xFF` ⇒ 实测点亮
  **38.02 / 92.02 / 110.02 / 151.04 µs**、搬运落点 **消隐/消隐/点亮/点亮**、Note 7②/7③ 各 **0 次**、
  每扫描 384 个 CLKa、扫描周期 189.04 µs、刷新 123.02 Hz；四份 `check_seed_window.js` exit 0、
  `--compliance` **16/16 全 ✅**。
* **性能（2026-10-14）**：用 QEMU/Cortex-M0 + `-icount`（1 指令 = 1 虚拟 ns）做目标 ISA 指令计数，
  把两处热点改掉并上机复核：① 位重排改**表驱动 gather** —— 每帧 **124.4k → 43.9k 指令**（界面型内容，
  稀疏/稠密/全亮为 38.0k→33.1k、153.1k→49.9k、198.7k→49.9k），tick 的整帧位反序**折进打包**
  再省 27k 指令/帧（pio 输出逐字节不变，`wireOrder=false`）；② SSD1306 渲染行映射表 ——
  滚动中 `renderToFramebuffer()` **4.90 → 1.17 ms/次**（此前逐像素取模，M0+ 无除法指令）。
  单核上机（诊断开、屏幕横向+纵向滚动）：`render` **30% → 6%**、>4 ms 的长排水间隔 **51/54 → 0**、
  四项忙时合计 **75%/74% → 61%/60%**，`overrun/drop/resync` 恒 0。

## 8. 已知取舍

* ~~**峰值亮度 ≈47%**~~ → **2026-10-17 起亮度 20%–80%（38–151 µs）**：搬运用「落点两选一」满足 Note 7②
  （高亮度整段落在点亮窗口内、低亮度落在消隐窗口内），自洽性由 `src/vfd_pio_seed_timing.h` 的编译期
  `static_assert` 互锁。80% 档整机实测 ≈2.5 W @5 V（占手册电气包线 ≈89%），故不再上调。
* **BK 波形形态与手册样例的差异（已知偏差，2026-10-17 用户决策保留）**：手册 Sheet 5/9 的样例是
  「平时低（点亮）+ 每个时序边界两个 ≥5 µs 的窄消隐脉冲」，本实现是「一段消隐 + 一段点亮」
  （搬运用落点两选一：高亮度落在点亮窗口内、低亮度落在消隐窗口内）。**合规条款不受影响** ——
  Note 7②（写入期间 BK 不得变化）、Note 7③④、Note 16（桁间消隐 ≥5 µs）、刷新率都已按真机四档抓包
  + 黄金样本核对通过；差异只在「消隐在周期内怎么分布」。要完全恢复手册形态需要把 BK 改成
  「每周期两个高相位」（PIO/定时器产生），属独立一轮，**暂不做**。
* **双核把 SSD1306 数据面搬到 core1** 后 core0 只剩时序与发布；打包（2064 B 位重排）仍在 core0
  （2026-10-14 起已改为表驱动 gather，每帧 43.9k 指令量级，见 §7），若还要再省可搬 core1
  （需给帧发布加原子握手，风险更高，按需再做）。
* pio 引擎的**数据通路仍依赖 CPU 换帧**
  （`engineStalled()` 可查）。要做到完全脱离 CPU，可把整帧 DMA 做成自循环控制块链。
* pio 引擎靠 BK 引脚的电平沿同步，因此亮度 0 时仍保留最小点亮窗口（选项 C 起 = **38 µs**，占空 20%，即产品亮度下限）。
* **主机时钟 8 MHz**：协议层可用（不少库的默认值就是 8 MHz），但**余量随钟点翻倍而减半**
  （危险线 8.19 → 4.09 ms）。诊断开时 `gapmax` ≈2.79 ms，只剩 1.3 ms 余量；建议**先在 4 MHz 验收**，
  要上 8 MHz 就用 `gapmax` 与 `overrun/drop` 两个实测数字说话（量产 `-Diag off` 更宽松）。
* **长阻塞与从机丢字节**：已修（排水义务，见 §5），但本质上仍是"主循环不能被占住太久"的约束 ——
  加大环形缓冲治标不治本（平均速率跟不上时，环再大也会绕满）。
