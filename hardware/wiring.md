# 硬件接线与注意事项

## 1. 接线表（默认配置）

`RP2040（Pico）` ↔ `VFD 驱动板 J12`

| Pico GPIO | 驱动板 J12 | 驱动侧网络 | 说明 |
|---|---|---|---|
| GP2 | CLKA | SPI0 SCK | 阳极移位时钟，4.46 MHz、MODE3（空闲高）、LSB-first |
| GP3 | SIA | SPI0 TX | 阳极串行数据（384bit 链） |
| GP4 | LAT | LATa + LATg（板上并联） | 数据锁存，**空闲低、高脉冲锁存**（高有效）——2026-10-06 核对电路图确认驱动电路无反向器，手册画的正脉冲有效就是 MCU 侧波形 |
| GP5 | CLKG | CLKg | 栅极移位时钟，空闲高；先拉低、再拉高，**前进发生在上升沿** |
| GP6 | SIG | SIg | 栅极串行数据，仅帧首播种 `1,1,0,0,0` 共 5 个时钟 |
| GP7 | BK | BKa + BKg（板上并联） | 消隐/调光，PWM 输出（高 = 消隐） |
| GP8 | HVEN | HVEN | XL6007 升压使能（VDD2 ≈ 45 V），高有效 |
| GP9 | FLEN | FLEN | LM9022 灯丝驱动使能，**高 = 关断** |
| GND | GND | — | **必须共地** |

引脚可在构建时覆盖，例如：

```bash
cmake -S . -B build -DPICO_SDK_PATH=/path/to/pico-sdk \
      -DVFD_PIN_BK=15 -DVFD_PIN_LAT=14 -DVFD_DMA_TX_CH=2 -DVFD_DMA_RX_CH=3
```

约束：

* `VFD_PIN_CLKA/SIA` 必须是所选 SPI 实例的 SCK/TX 引脚（默认 `spi0` → GP2/GP3）；
* `VFD_PIN_BK` 必须是**支持 PWM** 的引脚（GP0–GP29 均可，代码用
  `pwm_gpio_to_slice_num/channel` 自动取 slice）；
* `VFD_DMA_*` 选两个未被占用的 DMA 通道（RP2040 共 12 个）。

### 1.1 使用 PIO 引擎（`-DVFD_SCAN_ENGINE=pio`）时的额外约束

| 项 | 约束 / 默认值 |
|---|---|
| `LAT / CLKg / SIg` | 必须是**连续三个 GPIO**（默认 GP4/GP5/GP6，顺序：LAT=base, CLKg=base+1, SIg=base+2）。不满足时 `platform.engineError()` 会置位且不启动扫描 |
| `CLKa` | 由 PIO sideset 产生；默认 4.5 MHz（`-DVFD_PIO_CLK_HZ`，须 ≤5 MHz） |
| `SIa` | 由 PIO `out` 产生（LSB-first） |
| `BK` | 仍是 PWM 输出，但 PIO 会**读取该引脚电平**用于同步，因此该 pad 的输入缓冲必须使能（代码已 `gpio_set_input_enabled`） |
| `VFD_PIN_SEED_FLAG` | 默认 GP10：CPU 输出、PIO 用 `jmp pin` 回读，**不需要任何外部连线**，但请避开已在用的引脚 |
| DMA | PIO 引擎只用 1 个通道（`-DVFD_DMA_CH`，默认 0），不需要 RX 通道 |
| 接线表 | **与 tick 引擎完全相同**，无需改线 |

### 1.2 作为 SSD1306 从机时（主机 → 本机）

| 主机 MCU | 本机 Pico | 约束 / 说明 |
|---|---|---|
| SCK / SCL | **GP11**（`VFD_EMU_PIN_SCK`） | SPI **模式 0**（CPOL=0, CPHA=0），建议 1–8 MHz |
| MOSI / SDA | **GP12**（`VFD_EMU_PIN_MOSI`） | PIO 的 `in_base` |
| DC / A0 | **GP13**（`VFD_EMU_PIN_DC`） | **必须 = MOSI + 1**（PIO 用 `in pins,2` 一次采 {MOSI,DC}）；代码会校验 |
| CS / SS | **GP14**（`VFD_EMU_PIN_CS`） | 低有效，本机内部上拉 |
| RESET（可选） | **GP15**（`VFD_EMU_PIN_RESET`） | 低有效；不接也可以（`-DVFD_EMU_PIN_RESET=255` 关闭） |
| 测试模式选择 | **GP16**（`VFD_PIN_TEST_MODE`） | 内部上拉；**上电为低** → 渲染内置测试图像；默认高 → 只做 SSD1306 从机 |
| GND | GND | **必须共地**（两板之间） |

资源占用：1 个 PIO 状态机（14 条指令）+ 1 个 DMA 通道 + 1 KB 环形缓冲。
若扫描引擎选了 `pio`（占 `pio0`），模拟器默认用 `pio1`（`VFD_EMU_PIO_INST=1`），互不冲突。

```
   主机 MCU                                    本机 RP2040 (Pico)
   ┌────────┐   SCK  ─────────────────────────► GP11
   │ SSD1306│   MOSI ─────────────────────────► GP12 ─┐
   │ 库     │   DC   ─────────────────────────► GP13 ─┴─► PIO: in pins,2 → word=(byte<<1)|dc
   │        │   CS   ─────────────────────────► GP14      → DMA 环形缓冲 → Ssd1306Emulator
   └────────┘   GND  ─────────────────────────► GND       → VFD 帧缓冲 → 123 Hz 扫描
```

## 2. 供电与上电顺序

* VDD1 = 5 V（逻辑），VDD2 = 45 V（显示，MAX 50 V），灯丝 2.9 Vac / 275 mAac。
* 驱动板由 XL6007 从 5 V 升压产生 VH，由 LM9022 产生灯丝交流。
* 代码里的上电顺序（`Rp2040Platform::powerUp()`）：
  1. `HVEN=0`、`FLEN=1`（关高压、关灯丝驱动），BK 设为消隐/半亮；
  2. `FLEN=0`（灯丝上电）→ 预热 `preheat_ms`（默认 400 ms）；
  3. `HVEN=1`（高压上电）→ 20 ms 稳定。
* `emergencyOff()` 的顺序相反：**先关高压，再停扫描**（手册 Note 14）。

## 3. 安全提醒

* 45 V 与灯丝交流都在驱动板上，**接线、改线、插拔时请断电**；
* 调试逻辑时序时建议断开高压（或让 `HVEN` 保持低），只观察 SPI/CLK/LAT/BK 波形与 BK 点亮窗口；
* 不要让栅极扫描长时间停止：本驱动有看护（停摆 → 恢复 → 紧急关断），但代码里的
  长临界区、长时间 `while` 阻塞、更高优先级中断仍会造成扫描抖动。

## 4. 需要示波器核对的关键点（首次点亮建议逐条确认）

1. CLKa 频率 ≤ 5 MHz（固件会打印实际值），空闲电平为高；
2. 每个扫描周期 189 µs（≈5.29 kHz）：CLKg 先拉低再拉高（**前进在上升沿**），随后 LAT 一个
   **高**脉冲锁存（有效电平均 ≥300 ns）——顺序是**先前进、再锁存**，反了会把画面整体平移 3 列；
3. 每帧 43 个扫描周期 ⇒ 帧率 ≈123 Hz；
4. BK 在数据传输期间保持高（消隐），点亮窗口落在周期尾部；
5. 栅极链：每帧 CLKg 共 48 个脉冲（5 播种 + 43 前进）。

### 4.1 SIg（栅极播种）核对 —— 两种引擎都应看到

| 看什么 | 期望值 |
|---|---|
| SIg 高电平 | **每帧一次**，宽度 ≈**1.9 µs**（覆盖 2 个 CLKg 脉冲 = 播种位 `1,1`），间隔 = 帧周期 **8.127 ms** |
| SIg 其余时间 | 42 个普通扫描周期内**恒为 0**（982 组单脉冲里 0 组 SIg 为高才算正常） |
| 帧首 CLKg 组 | **6 连发**（播种 5 + 该扫描的前进 1）；其余每扫描 1 个；每帧合计 **48** 个 |
| BK 上升沿 → CLKg 边界脉冲 | tick ≈**0.3 µs**；pio ≈**86.9 µs**（= 782 周期 ÷ 9.0014 MHz，实测 86.6–86.8 µs）。
⚠️ 该实测取自**早期程序结构**；现程序数据段 786 周期、边界四步占 786–802，**此值需抓一次包重新标定** |
| 串口 `seed_req=` | pio 引擎下应约等于经过的帧数（每帧申请一次播种） |

> **tick 引擎特别注意**：CLKg / LAT 的高电平也必须够宽（手册 Figure 3：tWCLK ≥ 80 ns、tWL ≥ 300 ns）。
> 早期 tick 版只保证低电平 1 µs，帧首播种脉冲的高电平只有十几 ns，栅极链数不清时钟，
> 表现为开屏画面重影/错列（详见综合报告 §8.11）。用示波器核对时，请同时量**高电平宽度**。

> **为什么 SIg 每帧只高一次、而 CLKa/SIa 一直在跑？** 两条链职责不同：阳极链每个扫描周期都要
> 整链重装（384 bit ≈ 85.3 µs），栅极链只需前进一位（1 个 CLKg 脉冲），**只有帧首那 5 个时钟需要数据**；
> 每帧 43（前进）+ 5（播种）= 48 = 链长。换算：每个 CLKg 脉冲对应 384 个 CLKa 周期，
> 每出现一次 SIg 数据脉冲，CLKa 已经跑了 16512 个周期 —— 详见综合报告 §2.1.1。
>
> 若 pio 版 SIg 一直是 0（历史上出现过：请求脚窗口错过 `jmp pin` 检查点，见综合报告 §6.5），
> 栅极链会每帧只被推进 43 次、图案无法自复位，屏幕会表现为无法正常扫描。

仓库自带分析脚本（不需要任何库）：

```powershell
node tests/tools/analyze_la_csv.js <CSV>                            # 通道名：Time[s], CLKa, SIa, LAT, CLKg, SIg, BK, HVEN, FLEN
node tests/tools/analyze_la_csv.js <CSV> --window 0.0024 0.000006   # 转储 2.4 ms 附近 ±3 µs 的原始样本
```

它会打印各信号电平宽度、CLKg 脉冲分组（1 连发 / 6 连发）、每帧脉冲总数、SIg 变化点与段宽、
BK→CLKg 相位，以及**采样间隔分布**（用来判断抓包是否丢样 —— 若存在几十 µs 的空档，
逐边沿计数就不可信，应以"SIg 高电平宽度与出现频率"为准）。

## 5. SSD1306 从机联调核对点

1. 上电日志（USB 串口）应打印 `mode: SSD1306 emulator`（测试脚为高）或
   `mode: TEST IMAGE`（测试脚被拉低）；
2. 主机侧用示波器确认 SCK 空闲为低、数据在上升沿稳定（模式 0），DC 在整字节期间保持不变；
3. 主机 `display()` 之后，日志里的 `rx=`/`data=` 计数应增加（每次整屏刷新 ≈1030 字节：
   21 个初始化/窗口命令 + 1024 数据），`overrun=`/`drop=` 应保持 0，`stall=0`；
4. 若画面不更新：检查 `DC` 是否真的接在 `MOSI+1`；`begin()` 失败时日志会打印原因；
5. `0x81`（对比度）命令会改变 VFD 亮度，可用来确认命令通路正常；
6. 滚动联调：主机发 `0x26/0x27/0x29/0x2A` 后 `0x2F`，画面应开始按间隔平移（`0x2E` 停在当场）；
   串口状态行的 `scroll:` 字段会显示 `active/mode/pages/interval(ms per step)/v/steps`。
## 6. SSD1306 滚动的观感核对

| 主机参数 | 本机行为 |
|---|---|
| `0x26`/`0x27`，间隔 7 | 每 **16 ms** 平移 1 列（最快档，肉眼为匀速流动） |
| `0x26`/`0x27`，间隔 0 | 每 40 ms 平移 1 列 |
| `0x29`/`0x2A`，垂直偏移 V | 每步右/左移 1 列 + 下移 V 行（窗口内循环） |
| `0x2E` | 立即停在当前位置（显存不再改写） |

> 逐帧速度取决于本机折算（1 帧 = 8 ms），与真实 SSD1306 的观感一致但非逐晶振复刻。
